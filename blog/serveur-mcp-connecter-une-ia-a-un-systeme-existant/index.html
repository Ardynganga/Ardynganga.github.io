Serveur MCP : connecter une IA à un système existant

Le protocole MCP permet à un assistant IA d'interroger vos outils et vos données sans réécrire votre système. Principe, exemple en Python et précautions de sécurité.

Un assistant IA sait rédiger, résumer et raisonner, mais il ne connaît ni vos commandes, ni vos stocks, ni vos dossiers clients. Pour qu'il devienne utile dans une entreprise, il doit pouvoir consulter vos systèmes, et parfois y agir. Le Model Context Protocol (MCP) est le standard ouvert qui décrit cette connexion.

Ce que MCP apporte

Avant MCP, chaque intégration était écrite sur mesure pour un assistant donné. MCP joue le rôle d'une prise universelle : vous écrivez un serveur qui décrit ce que votre système sait faire, et tout assistant compatible peut s'y brancher.

Un serveur MCP expose trois types d'éléments :

  • des outils : des fonctions que l'IA peut appeler, comme « rechercher une commande » ;
  • des ressources : des données consultables, comme un document ou une fiche ;
  • des modèles de requête : des consignes prêtes à l'emploi pour des tâches récurrentes.

Point important : votre système existant ne change pas. Le serveur MCP est une couche mince posée devant votre API ou votre base de données.

Un premier serveur en Python

Prenons une API de gestion de commandes déjà en service. L'objectif : permettre à un assistant de répondre à « Où en est la commande 1042 ? ».

pip install "mcp[cli]" httpx
import os

import httpx
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("gestion-commandes")

API = os.environ["API_URL"]
JETON = os.environ["API_TOKEN"]      # jeton en lecture seule, dédié à ce serveur


@mcp.tool()
async def rechercher_commande(numero: str) -> dict:
    """Retourne le statut et le montant d'une commande à partir de son numéro."""
    async with httpx.AsyncClient(timeout=10) as client:
        reponse = await client.get(
            f"{API}/commandes/{numero}/",
            headers={"Authorization": f"Bearer {JETON}"},
        )
        reponse.raise_for_status()
        commande = reponse.json()

    return {
        "numero": commande["numero"],
        "statut": commande["statut"],
        "montant": commande["montant"],
    }


if __name__ == "__main__":
    mcp.run()

Trois choses méritent l'attention :

  • La description de la fonction est lue par l'IA. C'est elle qui lui indique quand utiliser l'outil : rédigez-la comme une consigne claire.
  • Les types des paramètres deviennent le schéma que l'assistant doit respecter.
  • La fonction renvoie uniquement les champs utiles, pas la réponse brute de l'API.

Brancher le serveur à un assistant

Les clients compatibles se configurent en déclarant la commande qui lance le serveur.

{
  "mcpServers": {
    "gestion-commandes": {
      "command": "python",
      "args": ["serveur.py"],
      "env": {
        "API_URL": "https://api.exemple.test/v1",
        "API_TOKEN": "jeton-en-lecture-seule"
      }
    }
  }
}

En local, client et serveur échangent par l'entrée et la sortie standard. Pour un serveur partagé par une équipe, MCP prévoit aussi un transport HTTP.

La sécurité n'est pas une option

Donner des outils à une IA, c'est lui donner du pouvoir sur votre système. Quelques règles, tirées de la pratique du test d'intrusion :

  • Moindre privilège. Le serveur utilise un compte dédié, limité au strict nécessaire. Commencez par la lecture seule.
  • Validation des entrées. Ce que l'IA transmet à vos outils se traite comme une saisie d'utilisateur : jamais de SQL ni de commande assemblés à partir de ces valeurs.
  • Confirmation humaine pour toute action qui modifie, supprime ou engage de l'argent.
  • Méfiance envers le contenu. Un document ou un courriel lu par l'IA peut contenir des instructions cachées. Un outil ne doit pas pouvoir faire plus que ce que l'utilisateur a lui-même le droit de faire.
  • Journalisation. Chaque appel d'outil est enregistré : qui, quoi, quand, avec quels paramètres.

Par où commencer dans une entreprise

Le meilleur premier projet est modeste : un ou deux outils en lecture, sur une question que vos équipes posent tous les jours. Le suivi d'une commande, l'état d'un dossier, la recherche dans une procédure interne. Vous mesurez l'usage, vous ajustez les descriptions, puis vous ouvrez progressivement des actions d'écriture, toujours avec confirmation.

L'intérêt de MCP est là : vous ajoutez de l'intelligence à ce qui existe déjà, sans refonte, et vous gardez la main sur ce que l'IA peut voir et faire.
